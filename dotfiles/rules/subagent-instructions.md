# サブエージェントへの追加の指示

auto mode の許可判定は、サブエージェントへの最初の指示に書かれた禁止 (「コミットはしない」など) をユーザーの境界として扱う。
後から委託元が送る追加の指示は別エージェントの発言とみなされ、その禁止を解除できない。解除しようとすると、操作と無関係な理由で拒否される。

## ルール

- 追加の指示は、最初の指示の範囲内での補足 (対象の追加、観点の追加など) に限る。
  依頼した成果物への修正の依頼は補足に含む。ただし、最初に禁じた操作の解除を伴うものは含まない。
- 最初の指示で禁じた操作を、後から追加の指示で同じエージェントに行わせない。
  後で必要になりうる操作は、次のどちらかにする。
  - その操作は新しいエージェントか委託元が行う。最初の指示にもそう書く。
  - 禁止を「yy まで xx しない」の形で、解除のタイミングが自明な能動的な条件として書く。条件を満たしたら、エージェント自身が行う。
- 「xx しない。ただし、追加の指示で…」のように、後からの指示で解除する前提の条件は付けない。

## 例

良い例 (委託元が行う):

```
コミットは委託元が行う。コミットはしない。
```

良い例 (解除の条件を書く):

```
check が通るまでコミットしない。
```

悪い例 (後からの指示で解除する前提):

```
コミットはしない。ただし、追加の指示でコミットを指示する可能性がある。
```

悪い例:

```
このパスは探索しない。ただし、追加の指示で探索を指示する可能性がある。
```
