# 成果物として残る文章の書き方

GitHubの issue や PR、コミットメッセージやドキュメントなど、会話の外に残り、後から第三者が読む文章に適用する。
Claude Code 上でのユーザーへの応答・説明・要約はこのルールの対象外であり、通常どおりでよい。

## ルール

- 文体は である調 で統一する。
  ですます調と混在させないこと。
- 宛先のない返信調にしない。
  依頼者との会話の続きをそのまま書かない。「ありがとうございます」「ご指摘のとおり」といった応答表現は、その場に相手がいない限り使わない。何をどう変えたかを事実として書く。
- 経緯ではなく結果を書く。
  会話の文脈を知らない読み手が、単体で読んで理解できる記述にする。

## 例

悪い例（commit message 本文）:

```
ご指摘のとおり、設定の読み込み順が逆になっていたので直しました。
ありがとうございます。
```

良い例:

```
設定の読み込み順を user → project の順に修正する。
project 側の値が user 側で上書きされる不具合を解消する。
```
